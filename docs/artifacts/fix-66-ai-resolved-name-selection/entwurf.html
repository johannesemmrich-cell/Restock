Issue #66 · Bon-Prüf-Karte

Gleicher Name,
zwei Wege

Löst die KI ein Bonkürzel auf denselben Namen auf, der schon unabgehakt auf der Liste steht, zeigt die Karte heute keinen markierten Kreis — obwohl oben der richtige Name steht. Alltagsfall: „Butter“ steht unabgehakt auf der Liste, die Bonzeile BTR wird von der KI zu „Butter“ vervollständigt.

Neu: Trifft der bestätigte Text einen Vorschlag exakt, übernimmt er dessen Verknüpfung zum Listenartikel — die KI-Kennzeichnung weicht der Listen-Herkunft. Aus einem einzigen, ohnehin naheliegenden Tap wird die Reparatur, ohne dass eine zweite Zeile je sichtbar war.

Variante C — Wurzelfix im Hintergrund

Sieht auf dem Bildschirm identisch zu Entwurf A aus — der Unterschied liegt unsichtbar im Hintergrund: die Verknüpfung zum Listenartikel würde schon bei der Namensauflösung selbst hergestellt, nicht erst in der Karte korrigiert.

Dafür würde die Bon-Erkennung Preise künftig auch für unabgehakte Artikel automatisch zuordnen — heute macht sie das bewusst nicht. Größerer Eingriff in das Lernverhalten, kleinerer Eingriff in die Karte selbst.

Unabhängig von der Wahl: eine Randlücke wird mitgeschlossen

Ändert sich im Hintergrund nur die Verknüpfung, nicht aber der angezeigte Name selbst, prüft die Karte aktuell gar nicht neu, ob ihre Markierung noch stimmt.

Das wird unabhängig von A/B/C mitbehoben — reine Korrektheit, keine Gestaltungsfrage.

Empfehlung

Entwurf A, ergänzt um das aufgewertete „Anderer Name“-Feld. Eine Zeile auf dem Bildschirm, keine Doppel-Namen — und die Zusage „markiert = verknüpft“ bleibt trotzdem reparierbar, weil das ohnehin vorhandene Feld die Reparatur übernimmt, statt dass es dafür eine eigene, stets sichtbare zweite Zeile bräuchte.

Kein Eingriff in die automatische Preis-Zuordnung (anders als Variante C) — die Verknüpfung entsteht nur, wenn der Nutzer selbst einen Namen bestätigt, nie automatisch beim Einlesen des Bons.
